# GPS、圈速与冲刺

## 职责与边界

| 文件 | 职责 |
| --- | --- |
| `gps.c`、`gps.h` | 配置 UM982 并确认回执，解析 NMEA（RMC 速度/状态/位置、GGA 定位质量/卫星数、GSV 信噪比、GPHPR 双天线航向），估算信号等级，累加里程，按节拍发送 GPS CAN 帧，维护诊断统计 |
| `gps_speed.c`、`gps_speed.h` | RMC 速度与位置的有效性：新鲜度门限、重复/倒退历元、失效原因、连续性序号；无硬件依赖，屏幕、CAN、计时和 CLI 共用这一份状态 |
| `speed_trace.c`、`diag_cli.c` | 车速到屏幕的耗时追踪、USART2 诊断命令行，见 [串口诊断 CLI](diagnostics.md) |
| `gps_lap.c`、`gps_lap.h` | 圈速（起终点线过线检测、圈差）与 S 模式 75 m 冲刺计时，不接触硬件 |
| `dashboard_ui.c` | 触摸或 CAN 触发计时开始/停止，选线方向，模式锁，提交圈速到界面 |
| `odometer_flash.c` | 里程的 Flash 存储，见 [里程存储](odometer_storage.md) |

输入是 UM982 的 NMEA（USART3，115200，循环 DMA）；输出是界面数据（车速、信号、里程、圈时、圈差）和 CAN 帧（见 [CAN 接口](can_interface.md)）。常量见 [配置表](configuration.md)。

## 处理流程

GPS 任务（优先级 25，栈 12 KiB）上电后等界面就绪，读出里程，等待首条 NMEA（最多 5 s，期间每 20 ms 处理一次 DMA），再依次发送接收机配置命令并确认回执（见下）。之后每 10 ms：处理 DMA 中新到的字符 → 行解析 → 位置与速度有效性检查 → 检查 GGA/GSV 过期 → 执行 CAN 发送节拍 → 处理 CLI 请求。配置命令发送期间同样每 10 ms 读取 DMA，512 字节缓冲区在 115200 baud 下约 44 ms 绕回，若一次读取间隔过长会记入 `g_gps_dma_late_poll_count` 并更新 `g_gps_poll_gap_max_ms`。不使用串口空闲中断，避免噪声把中断变成高频唤醒源。

**串口错误恢复**：HAL 在 DMA 接收遇到任何串口错误（帧、噪声、校验、溢出）时会中止接收且不自动恢复，不重启则 GNSS 数据永久中断。`HAL_UART_ErrorCallback` 把错误转给 `GPS_UartErrorCallback`，按位计数并重启循环 DMA；任务在每次轮询时也检查接收状态作兜底。重启后环从下标 0 写起，任务丢弃旧读位置和半行数据。USART2（命令行与圈速差）的单字节中断接收同样在错误回调里重新启动。

**语句分类**：按地址字段末三个字符识别 RMC/GGA/HPR/GSV（`$GNRMC`、`$GPRMC` 等），不在整行里搜索。接收机对 `GPRMC` 命令的回执 `$command,GPRMC 0.05,response: OK` 也含 "RMC"，按子串匹配会把它当成状态为 V 的 RMC 并使车速失效。

**车速**：RMC 速度（节）换算为 0.01 km/h 并限幅到 300 km/h。界面显示整数 km/h，**每次被接受的 RMC 都立即提交**；CAN `0x301` 为 0.1 km/h。

**速度有效性**（`gps_speed.c`）统一回答"现在有没有可信速度"，屏幕、CAN、圈速、冲刺和 CLI 都读它，不再各自清零或保持：
- 被接受的 RMC：校验和通过、状态 A 且模式指示不是 N、速度字段是合法数字、UTC 历元相对上一条前进。空速度、非数字、负数不是 0 km/h，该条不续期；重复或倒退的历元（按 UTC 当日毫秒模 24 小时比较，跨午夜正常）不续期；时间字段只有整秒时无法区分同秒内多条，跳过这项检查；静默超过 1 s 后历元基准作废（接收机重启后时间可能变小）。
- 新鲜度门限 = 3 个实测输出周期，夹在 150..1500 ms：20 Hz 为 150 ms，10 Hz 为 300 ms。周期是被接受 RMC 间隔的滑动平均，偶发断流不抬高门限；连续三次间隔都超过门限才认为接收机输出率真的降低（如配置没生效退回 1 Hz），之后门限在十来条内跟上，上限 1500 ms。具体值待实测收敛。
- 超过门限：界面显示 `--`（不是 0），速度为 0 但 `speed_valid` 为 0；RMC 状态 V 立即失效，不等门限。正常收到可信速度时立即更新，恢复后的第一条新数据立即生效。"有效的 0 km/h"显示 `0`，"没有可信速度"显示 `--`。上电后到首条可信 RMC 之前也显示 `--`。
- CAN `0x301`：无效时发 0，同时 `0x068` 状态位 `RMC_VALID` 清零，接收方据此区分。CAN 侧失效门限仍为 500 ms（`GPS_CAN_SPEED_STALE_MS`），与本地门限对齐以及 `0x7A0` 状态在有效性变化时立即补发，均需先在 `vehicle-interfaces` 评审，当前未改变 CAN 行为。
- 每次在失效后重新接受数据，连续性序号 `continuity_seq` 加一，计时模块据此识别断流。

**位置与航向**各有自己的新鲜度：RMC 经纬度跟随速度的门限；GGA 定位质量超过 3.5 s（3.5 个 1 s 周期）未更新按"无定位"处理，`valid` 要求 GGA 有定位且 GGA 与 RMC 位置都新鲜；GPHPR 超过 1.5 s 无效；GSV 12 s。

**信号等级**（0..4）：优先用 GSV 平均信噪比（42/35/28/20 dB-Hz 为 4/3/2/1），GSV 缺失或超过 12 s 未更新时用 GGA 卫星数估计（≥16/12/8/4），GGA 表示无定位则为 0。

**航向**：GPHPR 双天线航向超过 1.5 s 未更新则无效。圈速线方向 = 双天线航向 + `GPS_HEADING_INSTALL_OFFSET_DEG`（有效时，静止也可用）；无效时回退到 RMC 航迹，且要求车速 ≥ 5 km/h，否则界面提示 `wait heading or move`。异常航向和超范围数字在解析时直接拒绝，避免归一化死循环和整数溢出。

**里程**：每个 RMC 位置与上一点按局部平面求位移。车速低于 1.00 km/h、采样间隔超过 2 s、单步超过 50 m、或超过按车速估算值 3 倍加 3 m 的步长一律丢弃，亚米部分累积到下一步。速度失效后恢复（`continuity_seq` 变化）或状态 V 时重建位置锚点，不跨断流累计距离（宁可少计）。每增加 100 m 写一条 Flash 记录；界面以 0.1 km 显示。

## 圈速

1. **开始**：在非 S 模式点触顶栏（或方向盘圈速计时键，见 [方向盘与车手屏](steering_wheel.md)）。要求 GPS 已定位且信号等级 > 0，否则弹出 `gps not fixed` / `gps no signal`。当前位置与线方向成为起终点线（同一条线），线垂直于方向。
2. **布防**：车辆离线超过 10 m 后才检测过线，避免起点误触发。
3. **过线**：相邻两个定位点从线的后侧（forward<0）穿到前侧（≥0），且交点横向偏移不超过门半宽（2.5/3.0/4.0 m，按定位质量），即判定过线；偏出为 `GATE_MISS`，反向穿越为 `REVERSE_PASS`，这两种和成功的 `CROSSED` 都在诊断中保持 2 s。过线时刻按两点间线性插值，减小 20 Hz 采样的量化误差。
4. **圈时与圈差**：本圈用时 = 过线时刻之差。最快圈刷新时保存其轨迹（最多 512 点）作参考；行驶中按位置在参考轨迹上插值得到参考用时，实时圈差 = 当前用时 − 参考用时；没有参考圈时，过线时的圈差为 0。圈数加 1，`0x7A0/0x7A1` 立即补发一次。
5. **结束**：再次点触关闭分析，计时状态停止；开始新一轮前 `GPS_Lap_Reset` 清空圈数、最快圈和参考轨迹。

**断流恢复**：计时中速度/位置失效后恢复（`continuity_seq` 变化），或定位失效、坐标非法时，旧位置锚点作废，中断期间不用旧位置判定过线或插值，恢复后的第一个样本只重建锚点。过线可能恰好发生在中断里而被漏掉，所以这一圈的用时标记为不可信：照常显示为上一圈并弹出 `lap time uncertain`，但不成为最快圈、不保存为参考轨迹、不计圈差。

诊断状态（`GPS_LapDiagState_t`）：`INACTIVE`、`WAIT_ARM`（未布防）、`ARMED`、`APPROACHING`（线前 30 m 内且横向在 2 倍门半宽内）、`GATE_MISS`、`REVERSE_PASS`、`CROSSED`，用于界面计时点的颜色。

## S 模式 75 m 冲刺

1. **准备**：S 模式下点触顶栏，要求已定位、**速度有效**（否则提示 `gps speed invalid`，失效速度的 0 不是停车）、车速 < 0.5 km/h（否则提示 `stop before ready`），方向取圈速同一套规则。界面显示 READY 与剩余 75 m；此时的位置和方向只是初值。非 S 模式没有双天线航向时圈速也要求速度有效。
2. **起步**：车速首次越过 0.5 km/h 时，按前后两个样本的速度线性插值，得到起步位置和起步时刻，**75 m 从这个插值位置量起**并开始计时，从而去掉大部分 GNSS 采样周期带来的误差。
3. **进行**：沿起点方向累计前进距离；单步位移超过 `8 m + 3 × 车速估算值` 的突跳被拒绝，保留上一个可信锚点以便恢复。界面显示剩余整米。
4. **完成**：前进距离首次达到 75 m，按线性插值得到完成时刻，记录用时，圈数加 1，弹出 `75m run complete`。再次点触在进行中则取消（`75m run cancelled`）。

**断流恢复**：READY 阶段断流后恢复时，若车速已越过 0.5 km/h，起步位置和时刻不可知，这次冲刺作废（`gps lost, run void`）；仍静止则只重建锚点，计时不受影响。进行中断流恢复时，以恢复后的第一个样本重建锚点（位移合理性检查不跨中断），结果弹出 `75m done (gps gap)` 标记；若终点在中断期间越过，不能用中断前的旧位置插值，同样作废。

## 模式锁

计时进行中（S 模式的冲刺进行中，或其他模式的圈速分析中）驱动模式被锁定：界面拒绝切换并弹出 MODE LOCK 告警，方向盘 `0x310` 也不再转发给 ECU（`Dashboard_UI_IsTimingModeLocked`），影响见 [方向盘与车手屏](steering_wheel.md#计时与模式锁)。冲刺准备（READY）阶段也算进行中。

## 并发

圈速/冲刺状态由互斥量保护（`GPS_Lap_InitLock` 创建）；界面的计时值和更新标志按一个事务交换。`GPS_Lap_Tick`、`GPS_Sprint_Tick` 在 Dashboard 任务中刷新圈时，`GPS_LapProcess`、`GPS_SprintProcess` 在 GPS 任务中随每个定位点调用。

## 故障与降级

| 情况 | 行为 |
| --- | --- |
| 无定位或信号等级 0 | 拒绝开始计时并提示 |
| 速度数据过期、状态 V | 界面 `--`，CAN 报 0 且 `RMC_VALID` 清零；拒绝准备冲刺 |
| 计时中速度/位置失效后恢复 | 重建锚点，不跨中断判定过线；这一圈或这次冲刺标记为不可信或作废，见上 |
| 计时中定位丢失或坐标非法 | 该样本被忽略，旧锚点作废，这一圈标记为不可信 |
| GPHPR 过期 | 回退到 RMC 航迹（需 ≥5 km/h） |
| USART3 错误 | 回调统计并重启 DMA 接收，数据中断到恢复期间按断流处理 |
| 接收机上电未就绪 | 等待 5 s 首条 NMEA 后继续；命令可能被丢弃，下次上电重试 |
| 命令无回执 | 每条重发至多 2 次，仍无回执记 `no_ack` 并继续；连续两条无回执后放弃确认，其余命令按固定时间等待，启动配置最坏多耗约 2.4 s |
| 过线门偏出 | 不计圈，诊断 `GATE_MISS` 2 s |
