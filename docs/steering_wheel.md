# 方向盘与车手屏

方向盘上有一块独立的按钮板（STM32F103，固件在 `Steering_wheel` 仓库），车手屏是本仓库的仪表固件。二者用一条专用 CAN 总线相连，不在整车 CANB 上。本文说明两块板各做什么、方向盘上每个控件最终起什么作用、一次操作如何走完全程，以及目前已知的限制。

相关文档：整个 CAN 网络的分工见 [CAN 网络分工](can_network.md)；帧的字节布局和超时见 [CAN 接口](can_interface.md)；两边的代码细节见 [方向盘相关代码](steering_wheel_code.md)；计时算法见 [GPS、圈速与冲刺](gps_lap.md)。

本文依据两边的源码（方向盘 `Steering_wheel` 提交 `cb60d69`，车手屏当前代码）整理。没有总线抓包，也没有上板或实车验证，凡写“按代码”的地方都是读代码得出的结论。

## 分工

| | 方向盘按钮板 | 车手屏 |
| --- | --- | --- |
| 硬件 | STM32F103C8T6，裸机轮询 | STM32F407ZET6，FreeRTOS，LVGL 驱动 800×480 屏 |
| 做什么 | 读取旋钮、电位器、两个按键，把操作变成 CAN 帧发出 | 显示整车数据；接收方向盘帧；GPS 圈速与冲刺计时；把方向盘的操作转发或合并后发给 ECU |
| 不做什么 | 不显示，不计时，不判断操作能否生效，不与 ECU 直接通信 | 不读取方向盘上的硬件，也不向方向盘发送任何帧 |

方向盘只报告“发生了什么操作”。操作是否生效由车手屏（计时、模式锁）和 ECU（驾驶模式、滑级、清错）决定。

## 连接

```
方向盘按钮板 ──专用总线 500 kbit/s，单向──▶ CAN2 车手屏 CAN1 ◀──整车 CANB 500 kbit/s──▶ ECU、BMS、PDM、风扇…
```

- 专用总线上方向盘只发送，车手屏的 CAN2 只接收（硬件会自动应答），车手屏不在这条总线上发任何帧。
- 方向盘不在 CANB 上。方向盘的操作进入整车只有一条路：车手屏收到后，在 CANB 上转发 `0x310` 或发出合并帧 `0x703`。
- 车手屏自身的驾驶模式色块也能直接向 ECU 发 `0x310`，这是方向盘之外的第二条模式请求路径，不经过 CAN2。
- 因此车手屏断电或未启动时，方向盘的操作到不了 ECU。

## 方向盘上的控件

| 控件 | 方向盘引脚 | 方向盘发出的帧 | 车手屏的反应 | 车手屏发给 ECU 的内容 |
| --- | --- | --- | --- | --- |
| 旋钮（4 档 S1..S4） | PA6、PA7、PB0、PB1 | `0x310` 驾驶模式请求，换档时发一帧：byte0 为 ASCII `0`..`3` | 界面模式色块切换为 S/Q/C/E；计时进行中拒绝并弹出 `MODE LOCK: TIMER ACTIVE` | 计时未锁定时在 CANB 上原样转发 `0x310`；计时中不转发 |
| 电位器 | PA1 | `0x700` 滑级 0..7，数值变化时发 | 界面 SLIP 等级条 | `0x703` 的 byte0 |
| KEY1 圈速计时键 | PB12 | `0x701`，松开时发一帧 | 开始或停止圈速/冲刺计时，与触摸顶栏效果相同 | `0x703` 的 byte1 bit0（DBC 名 `RecorderToggle`） |
| KEY2 消错键 | PB13 | `0x702`，松开时发一帧 | 清除界面上的全部告警（含排队中的）；触摸告警条只消除最早一条 | `0x703` 的 byte1 bit1 |

说明：

- 旋钮四档对应的模式：S、Q、C、E，按代码注释分别是直线加速（75 m）、避障、八字绕环、耐久。
- `0x701` 的 DBC 信号名 `RecorderToggle` 是沿用的旧称，实际功能是圈速计时键，与录像、相机无关。
- “消错”目前在车手屏上只是清除界面告警；它在 ECU 侧的含义暂定，ECU 如何处理 `0x703` 的清错位待确认。
- ECU 是否使用 `0x703` 里的计时位待确认。圈速计时本身完全在车手屏完成，不依赖 ECU。
- 中央库已删除 `0x784`（冗余驾驶模式）：方向盘固件不发送，车手屏不订阅。

## 一次操作的完整过程

### 按下并松开圈速计时键

1. 松开约 40 ms 去抖后，方向盘发 `0x701`，bit0=1，一帧；不重复，也不发 0 帧。
2. 车手屏 CAN2 收到，判定为一次新按下（距上一次不足 300 ms 的帧视为同一次，见下文限制）。
3. 车手屏通知界面切换计时：
   - **非 S 模式**：第一次开始圈速分析，要求 GPS 已定位且信号等级 > 0，当前位置和航向成为起终点线；条件不满足时弹出 `GPS NOT FIXED`、`GPS NO SIGNAL` 或 `WAIT HEADING OR MOVE`。再按一次停止。
   - **S 模式**：第一次进入 READY（要求车速 < 0.5 km/h，否则提示 `STOP BEFORE READY`），起步后开始 75 m 计时；进行中再按则取消并提示 `75M RUN CANCELLED`。
4. 同时车手屏在 CANB 上发 `0x703`（DLC 2），byte0 为当前滑级，byte1 bit0=1。

### 按下并松开消错键

1. 方向盘发 `0x702`，bit0=1，一帧。
2. 车手屏清除界面上的全部告警（包括排队中和尚未显示的），并在 CANB 上发 `0x703`，byte1 bit1=1。

### 拨动旋钮

1. 旋钮每换一个档位，方向盘发一帧 `0x310`。换档途中若出现没有档位或多个档位同时接地的状态，方向盘会发一帧 byte0=0xFF 的无效值，车手屏丢弃它。
2. 车手屏检查 byte0 是否为 ASCII `0`..`3`。
3. 计时没有锁定：把这帧 `0x310` 以原 ID、原 DLC 转发到 CANB，同时界面立即显示新模式。随后 ECU 在 `0x509` 里回报的模式会再次校正界面显示，ECU 回报 −1（默认模式）时界面保持不变。
4. 计时已锁定：不转发，界面不变，弹出 `MODE LOCK: TIMER ACTIVE`（同一告警 1 s 内只弹一次）。

### 点击车手屏模式色块

1. 触摸左栏 84×84 的模式色块，触摸范围外扩 8 px；200 ms 内的重复按下只算一次。
2. 车手屏在 CANB 上发送 `0x310`（DLC 8，byte0 为下一模式的 ASCII `0`..`3`，byte1..7 为 0），同时把界面切到下一档。
3. 顺序固定为 S→Q→C→E→S。ECU 在 `0x509` 中回报的模式会再次校正界面；若 ECU 不接受请求，界面最终会回到其回报的实际模式。
4. 计时锁生效时与旋钮相同：不发送、不换档，弹出 `MODE LOCK: TIMER ACTIVE`。发送队列满时不改界面，提示 `MODE TX QUEUE FULL`。
5. 触摸点击不会改变方向盘旋钮的物理位置，下一次拨动旋钮仍以新档位发出请求。

### 转动电位器

1. 量化后的滑级变化时，方向盘发 `0x700`。
2. 车手屏更新界面滑级，并在 CANB 上发 `0x703`，byte0 为新滑级。
3. 滑级具体控制什么由 ECU 决定，本仓库没有 ECU 侧的资料。

## 计时与模式锁

圈速分析进行中，或 S 模式的冲刺 READY/进行中，驾驶模式被锁定：

- 旋钮的 `0x310` 不再转发给 ECU，模式色块点击也不发送，界面都不换模式；
- ECU 在 `0x509` 里回报的模式变化同样不会改变界面，只触发 `MODE LOCK` 告警；
- 停止计时后锁解除；重新开始计时会清空圈数、最快圈和参考轨迹。

锁的目的是保证一次计时中模式不变，圈速结果可比。

## 上电、掉线与已知限制

以下由代码推出，未上板验证。

1. **上电首帧大概率丢失。** 方向盘上电后各发一帧滑级和模式，之后只在变化时才发。车手屏的 CAN2 在 `main()` 里早启动，但界面初始化完成前收到的帧会被丢弃。若车手屏比方向盘晚就绪（LCD 初始化需要时间），这两帧丢失，之后车手屏不会向方向盘查询。
   后果：界面滑级显示 0，直到电位器被拨动；在此之前按下计时键或消错键，车手屏发出的 `0x703` 带的滑级是 0，而不是电位器的实际位置。
2. **计时中拨旋钮后不同步。** 方向盘只在换档时发一帧，车手屏在锁定期间不转发；解除锁定后方向盘不会重发，ECU 仍是原模式，旋钮位置与实际模式不一致，需再拨动一次旋钮。
3. **连按间隔小于 300 ms 的两次按键会被当作一次。** 方向盘每次按键只发一个 1 帧、不发 0 帧，车手屏靠 300 ms 间隔（`CAN_BUTTON_REPEAT_GAP_MS`）区分两次按下。
4. **车手屏不检测方向盘是否在线。** 方向盘断线或断电时，界面保持最后的滑级和模式，不报警。
5. **方向盘的 CAN 进入 bus-off 后不会自动恢复。** 方向盘固件关闭了自动 bus-off 恢复，也没有软件处理，进入 bus-off 后按钮板不再发送，直到复位。
6. 车手屏未启动或没有应答时，方向盘的发送邮箱会持续重试，三个邮箱满后新帧被丢弃。
7. 触摸模式色块没有 ECU 确认握手，界面先乐观切到新模式；ECU 是否执行只能看后续 `0x509` 回报。请求帧已按现有 `0x310` 格式发送，未新增字段或 DLC。

## 待确认

| 项 | 需要谁确认 |
| --- | --- |
| `0x701/0x702` 是否确为“松开发一帧、不发 0 帧”；`0x310` 实际 DLC 是否为 8 | 方向盘负责人，抓包 |
| ECU 是否使用 `0x703` 的计时位和清错位，“消错”的最终含义 | ECU 负责人 |
| 上述限制 1、2 是否需要处理：方向盘周期性重发当前状态，或车手屏上电后等到首帧再发 `0x703` 滑级 | 方向盘与车手屏负责人 |
| 专用总线的终端电阻和线束长度 | 本仓库与方向盘仓库均无记录 |

对外帧的评审在 `vehicle-interfaces` 仓库进行，见 [CAN 接口](can_interface.md#与中央库尚未对齐的部分)。
